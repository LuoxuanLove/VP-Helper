# VP Helper 0.1.0 Preview 7

本次更新主要解决同步过程中对不可用接口反复重试的问题，并打通「同步提交 → 自动关联比赛 → 获取官方榜单」流程。

## 同步更快、更清楚

- CF 返回 HTTP 400 等确定性错误时停止重复请求，并保留具体错误原因；临时网络故障仍按限速规则有限重试。
- 参赛类型补全失败按账号和比赛保存 6 小时冷却，避免每次同步重复等待。已抓取的提交继续保留，界面明确提示待补全项目。
- 复用已核实的克隆关系和同轮父比赛页面；历史关系补全每轮最多 5 场，逐场保存进度。QOJ 题目映射缓存 7 天。
- 增加请求超时、取消同步按钮和阶段提示，移除与实际工作量无关的 95% 进度；修复迟到的进度消息覆盖完成状态的问题。
- 「上次同步」改为实际完成时间，不再使用最新提交时间代替；修复 CF 新增提交后的总数缓存。

一次本地实测中，同批 16 个不可用 CF 接口的检查由接近 18 分钟缩短到约 32 秒；冷却生效后的无新增提交同步，包含自动关联与榜单检查，共用时 5.3 秒。这是特定账号和网络环境下的观测，实际耗时取决于数据量、网络和站点状态。

## 自动关联与官方榜单

- CF/QOJ 账号同步后，自动按已核实的赛事链接与克隆关系关联比赛，再获取关联比赛缺失或过期的榜单。
- 保留人工确认的关联；目录外比赛继续支持手动关联，不按相似标题猜配。
- 官方比赛页新增「更新目录和榜单」操作，可刷新完整官方数据。
- 公开榜单文件最多 4 个并行下载，数据库逐场原子保存；下载失败保留原有完整榜单，报告失败数量。
- 修复重复刷新榜单时题目记录的跟踪冲突。
- 筛选后的「其中已 VP」只统计当前筛选结果，不再显示全目录总数。

榜单来自 [algoux/srk-collection（AGPL-3.0）](https://github.com/algoux/srk-collection)。本次对源提交 `1bbf1f2926e0c8db76986b8f2629ef8294ab9654` 的 394 场榜单完成全量更新验证。发行包不包含开发者的数据库、账号或浏览器登录状态；请在应用中更新自己的榜单。

## 开发与维护

- 新增 `tools/Start-Dev.ps1`，通过标准 .NET MSBuild Run 启动本地构建，沿用原有数据目录，不修改 Windows 安全设置。
- 新增官方榜单维护工具，可从固定版本的 srk-collection 快照更新指定数据库，并在写入前创建 SQLite 一致性备份。
- 新增错误重试、冷却、克隆缓存、自动关联、榜单刷新和筛选统计回归测试；本地 366 项离线测试通过，并完成 Windows 构建与实际窗口验收。

## 下载、安装与升级

1. 下载 `VPHelper-0.1.0-preview.7-win-x64.zip` 并完整解压；`source.zip` 是对应源码，不是安装包。
2. 首次使用运行 `VPHelper.WinUI.exe`。便携包包含 .NET 和 Windows App SDK，仍需安装 Microsoft WebView2 Evergreen Runtime。
3. 从旧版升级时，先关闭应用并备份旧目录中的 `data` 文件夹，再将该文件夹复制到新版 EXE 同级目录。首次启动会补齐新增字段。
4. 使用 `SHA256SUMS.txt` 校验附件。完整说明见包内 `INSTALL.md`。

本版本仍为未签名的 Windows x64 预览版，Windows 可能提示无法验证发布者。部分 CF 比赛的 API 仍可能返回“比赛不存在”，相关参赛类型会显示待补全；本次更新不会使站点未提供的数据凭空可用。完整安装环境和稳定版限制请参阅仓库文档。
